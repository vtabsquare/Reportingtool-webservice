# Stale Dashboard Cache Fix After Semantic Model Refresh (2026-11-26)

## Symptoms
- Running a refresh from the Unified Data Model (`Refresh History`) completed with `Succeeded · 2 tables · 553 rows` (`503` orders + `50` customers) at `1:23:16 PM`.
- Opening the dashboard (`/?workspace=1&report=b5ed5667-5081-4f5e-b2ec-e1e7c50319b5`) at `1:25 PM` still displayed `Data updated 11/26/2026 01:21 PM` and `Total Orders: 502.00`.

## Root Cause
1. **300-second blind cache in `_get_cloud_project`**:
   - Earlier viewer queries at `1:22 PM` populated `_cloud_project_cache` with the `1:21 PM` (`502` orders) `project_json`.
   - When the dashboard was opened at `1:25 PM`, `/api/v1/published/{report_id}/definition` and `/api/v1/published/{report_id}/query-batch` were called without `bypass_cache=1`.
   - `_get_cloud_project` returned the cached `1:21 PM` project for up to 300 seconds without checking whether `published_reports.updated_at` in Supabase had changed.
2. **Missing cache invalidation in `bridge_refresh_status`**:
   - Polling `GET /service/semantic-models/{id}/bridge-refresh/{job_id}` only called `invalidate_report_cache` in branch #3 (`vtab_bridge_refresh_jobs`), not in branch #1 (`refresh_runs`) or branch #2 (`scheduled_jobs`).
3. **Stale nested `report.updated_at` and viewer query dependencies**:
   - `_get_cloud_project` used `p_report.setdefault('updated_at', ...)` rather than updating `p_report['updated_at']` to the latest row timestamp.
   - `PublishedViewer.tsx`'s visual query `useEffect` did not include `item?.updated_at` in its dependency array.

## Fix
1. **`api/app/server.py` (`_get_cloud_project`)**:
   - Stores `updated_at` alongside `project` in `_cloud_project_cache`.
   - Keeps a 1.5s burst cache for concurrent page-load requests; after 1.5s (within the 300s window), checks `published_reports.updated_at` in Supabase.
   - If `updated_at` changed, calls `invalidate_report_cache(report_id)` (clearing `_cloud_project_cache`, `_HYDRATED_CACHE`, RLS cache, and `semantic_engine` DuckDB query cache) and reloads the fresh `project_json`.
   - Sets `p_report['updated_at'] = row.get('updated_at')` so nested report metadata always stays current.
2. **`api/app/data_bridge.py` (`bridge_refresh_status`, `_invalidate_semantic_model_reports`)**:
   - Added `_invalidate_semantic_model_reports` and invoked it whenever `bridge_refresh_status` returns `status == "succeeded"` across `refresh_runs`, `scheduled_jobs`, and `vtab_bridge_refresh_jobs`.
3. **`src/v11/PublishedViewer.tsx`**:
   - Added `item?.updated_at` to the page visual query `useEffect` dependency array.
